# README 视觉与版式升级

## 1. 做了什么

为公开仓库重新设计了 README 的视觉首屏和阅读节奏。新增一张深色科技风 Hero 横幅，用完整绿色盾牌、获授权的桌面应用和 PDF 输出表现“受保护文档通过正常权限快速转换”的流程；首屏增加双 CTA、统一徽章和章节导航。

正文不再是连续的大段说明，而是按“为什么做、是否适合、30 秒使用、核心能力、真实行为、工作原理、安全边界”逐层展开。用对照表快速讲清四个真实痛点，用适用性表格阻止不合适的用户误下载，用 GitHub 原生提示框强调权限、可见 WPS 和未签名 EXE，用 Mermaid 展示处理路径，并把源码运行与问题反馈收进折叠区。

## 2. 为什么做

上一版内容准确完整，但首屏主要靠文字，视觉记忆点弱，重要结论之间也缺少层级。第一次进入仓库的用户需要连续阅读几段，才能拼出“透明加密、WPS 获授权、Adobe 太慢、会员批量入口”之间的关系。公开产品不仅要讲对，还要让人一眼愿意继续看，并能在几秒内找到下载和适用条件。

## 3. 值得记住的决策、坑或技术点

横幅刻意不用 WPS、Adobe 或 Microsoft 的商标，避免让自制开源工具看起来像官方产品。首版生成图右侧出现了近似 Acrobat 的符号，因此又做了一次局部编辑，只替换为通用的 `PDF` 文字。

盾牌必须保持完整，不能使用破锁、破解或黑客视觉，否则会与项目“不解密、不绕权”的真实边界冲突。视觉表达必须服务于准确定位，而不是为了华丽制造误解。

README 使用 GitHub 原生支持的 HTML 居中、Markdown 表格、提示框、折叠区和 Mermaid，没有引入依赖外部站点的复杂页面。最终通过 GitHub Markdown 渲染接口检查，Hero、CTA、提示框、流程图和折叠内容均能正常识别。

## 4. 一句话亮点
