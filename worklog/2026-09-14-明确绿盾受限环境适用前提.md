# 明确绿盾受限环境适用前提

## 1. 做了什么

把项目定位从泛化的“WPS 批量转 PDF”进一步收窄为“绿盾等透明加密办公环境中的 WPS 批量转 PDF”。README 首屏现在先说明硬前提：普通 Python 或 headless 程序无法正常读取受保护文档，但当前用户必须能够通过本机 WPS 正常打开和导出。

新增了“先判断它是否适合你”的对照表，分别覆盖绿盾文档、Adobe 链路过慢、普通未加密文档、没有访问权限，以及非 Windows/服务器等场景。程序启动提示也改成了“适用于 WPS 可正常打开文档的绿盾环境”，版本提升到 `1.0.1`，重新构建了 Windows x64 EXE。

## 2. 为什么做

之前写“适配绿盾环境”仍然太宽泛，容易让人误以为工具能主动解密，或者所有 Word 转 PDF 场景都应该使用它。真实背景更具体：透明加密让普通脚本无法读取文件，只有被环境授权的 WPS 或 Adobe 能正常打开；而实际电脑上的 Adobe 转换链路太慢，所以才借助 WPS 的访问权限、转换速度和单文件免费导出能力来完成批量任务。

## 3. 值得记住的决策、坑或技术点

这个项目的护城河不是“会把 Word 转成 PDF”，而是“让获授权的桌面应用代替读不到密文的普通脚本完成转换”。因此最重要的适用条件必须放在下载按钮之前，不能藏在技术说明里。

未加密场景下确实有很多更轻、更通用的转换方案，但不能写成“Python 自带 Word 转 PDF”，因为 Python 标准库没有 Word 排版渲染器。README 改用“通用 Python、LibreOffice 或 headless 批量方案”的准确说法。

绿盾兼容也不是解密能力。程序只是保持 WPS 可见，并调用当前用户本来就有权使用的打开和导出流程；WPS 打不开、没有导出权限或企业策略禁止时，程序不会也不能绕过。

## 4. 一句话亮点

当加密文档只有获授权的 WPS 能打开，而 Adobe 转换又太慢时，就让 WPS 把整棵目录一次性快速导成 PDF。
