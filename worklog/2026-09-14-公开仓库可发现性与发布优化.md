# 公开仓库可发现性与发布优化

## 1. 做了什么

把原来只有源码和本机构建产物的目录，整理并发布成了公开仓库 `jedliuai/wps-batch-pdf-converter`。补齐了以用户价值为先的中英双语 README、MIT 许可证、运行依赖、构建说明和结构化 Bug 反馈模板；GitHub About 增加了双语 Description，把 Website 指向最新版下载，并设置了 WPS Office、Word to PDF、批量转换、Windows 自动化和 Tipray 等相关 Topics。

从当前源码重新做了一次干净的 64 位 Windows 单文件构建，发布为 `v1.0.0` Release。Release 中写明了真实能力、运行前提、安全边界和 SHA-256；GitHub 远端记录的摘要与本地构建一致。源码导入和语法检查通过，PyInstaller 构建成功，Microsoft Defender 自定义扫描没有记录到该产物的威胁检测。

## 2. 为什么做

原目录没有 Git 仓库、README、许可证、安装说明或 Release，用户即使偶然拿到源码，也很难迅速判断它能解决什么问题、是否会覆盖文件、是否上传数据、绿盾兼容到底意味着什么，更没有一个低门槛的可下载版本。公开发布后，需要同时照顾 GitHub、搜索引擎和 AI 搜索中的可发现性，以及陌生用户从第一次看到项目到愿意下载使用的完整路径。

## 3. 值得记住的决策、坑或技术点

仓库名采用可搜索、可引用的英文 `wps-batch-pdf-converter`，中文“WPS Word 批量转 PDF”继续放在 README 标题和程序界面里；这样兼顾国际通用叫法与中文用户搜索习惯，不靠堆砌关键词。

首屏最重要的信息不是实现原理，而是“本地运行、递归处理、支持 DOC/DOCX/WPS、已有 PDF 跳过、部分绿盾环境可用”和直接下载入口。边界也必须放在容易看到的位置：工具不解密、不绕过权限，只调用用户本机已有的 WPS 正常导出。

原来的 `logo.png` 不是有效 PNG，文件头异常，不能为了视觉完整硬塞进公开仓库；有效的 ICO 保留用于构建，坏的源图和本地生成脚本不发布。EXE 目前没有商业代码签名，因此 README 和 Release 都如实提示 SmartScreen 风险，并用公开源码、可自行构建和 SHA-256 校验来建立可验证的信任。

## 4. 一句话亮点

把散落在多层文件夹里的 DOC、DOCX、WPS 一次性用本机 WPS 转成 PDF：不上传、不覆盖，还照顾了天锐绿盾办公环境。
